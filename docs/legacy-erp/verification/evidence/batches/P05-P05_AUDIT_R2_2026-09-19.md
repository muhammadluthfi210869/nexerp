## Blocking findings

### P05-R2-B1 — Authoritative certification is not reproducible

`scripts/ssot/certify_p05_phase.js` calls `.trim()` on `git status --porcelain` output. When the first status line begins with a significant leading space (` M path`), `.trim()` removes it. `dirtyOutsideAllowlist()` then slices three characters and drops the first character of the path. A valid generated evidence modification is therefore rejected after the first run.

This is a defect in the frozen harness, not application implementation. R2 authorizes exactly one narrow frozen-wrapper amendment: preserve leading porcelain status bytes and remove trailing line endings only. Add a regression test for ` M`, `M `, `??`, quoted paths, and multiple allowlisted/non-allowlisted entries. No other frozen criterion, threshold, ID, base SHA, or success behavior may change. Record old/new wrapper hashes in R2 evidence.

### P05-R2-B2 — Mutation oracle does not verify the expected rejection

`expectProductionRejection()` captures `observedReasonCode`, but never compares it with `expectedReasonCode`. It then writes `reason_code: expectedReasonCode` regardless of what actually happened. Any exception—including a TypeError, setup error, or unrelated database error—can be reported as the expected production rejection.

The helper must require exact `observed gate_id` and `observed reason_code`, reject generic/unrelated exceptions, and store both expected and observed values.

### P05-R2-B3 — Multiple adversarial tests still synthesize their own rejection

Examples:

- domain-cycle mutation returns an invented `DOMAIN_CYCLE_DETECTED` result when the real gate reports zero cycles;
- cross-domain persistence inspects its own fixture string rather than invoking the production analyzer/gate;
- shared dumping-ground, orphan, complexity, duplicate-rule, and blast-radius mutations implement separate test-only detection logic;
- login-enumeration labels a normal bcrypt delay as a detected enumeration rejection;
- outbox nonatomic is an unconditional `{ status: 'FAIL' }` result with no mutation or production invocation;
- mention deduplication only runs `new Set()` on a local array;
- stale-evidence and unexpected-skip tests construct their own FAIL result rather than invoke the certifying validator.

A mutation passes only when the exact certifying gate/control itself rejects the mutation. Test-only reimplementation or fallback rejection is forbidden.

### P05-R2-B4 — Dependency graph and module-boundary analyzers cannot observe the claimed boundaries

`classifyImport()` returns `null` for every relative import and records only external package imports. `findForbiddenDomainImports()` subsequently searches recorded edges for `modules/`, which external package edges normally cannot contain. `findDirectCrossDomainPersistence()` is a constant `{ count: 0 }` implementation. The circular scan only recognizes import strings containing literal `modules/`, missing ordinary relative imports such as `../auth/...`.

Therefore dependency direction, forbidden domain imports, direct persistence reach-through, and many cycles can pass without being analyzed.

### P05-R2-B5 — Required metrics remain assigned rather than measured

The certification implementation assigns literal zero to architecture debt, orphan count, whole-code duplication delta, auth bypasses, tenant leaks, self approvals, audit mutations, outbox loss/duplicates, communication ACL bypasses, error violations, and unexpected skips. Control coverage is assigned `100`. These values are not derived from gate results or parsed test matrices.

`duplicate_dead_code_scan` still reports whole-code delta as literal zero and orphan count as literal zero. Every metric must originate from a gate result with nonzero observed targets and evidence.

### P05-R2-B6 — Representative-change gate does not rehearse changes

The gate calls `predictBlastRadius()` three times, but does not mutate any isolated candidate, does not execute targeted tests, and hardcodes `archetypes_passed: 3` and `prediction_coverage_percent: 100`.

Additionally, `predictBlastRadius()` searches source text for an absolute path or full repository-relative path; normal relative TypeScript imports will not match. It must resolve the AST/import graph and compare predicted versus actual touched/tested owners for three disposable rehearsals.

### P05-R2-B7 — Permission enforcement is not actor-to-permission authorization

`PolicyService` is described as database-backed but is instantiated without Prisma and accepts permission arrays from the actor object. If an actor has roles but no explicit permissions, the service permits an action whenever the permission slug merely exists in the global matrix. It does not prove that the actor's current role owns that permission. `RolesGuard` passes request user state directly to this decision.

The policy boundary must load actor-at-event role/permission/tenant/data scope from trusted persistence or a signed server-side authorization snapshot and map role → permission through the canonical matrix. A role must not gain every registered permission.

### P05-R2-B8 — Configuration ownership scan exempts the code it must police

The analyzer excludes all `backend/src/platform/**`, not only the approved configuration/bootstrap/safety boundary. `MfaService` still reads `process.env` directly. The frozen contract requires no module-specific environment reads outside the approved configuration boundary.

Inject typed `PlatformConfig` into services and scan all production files except narrowly enumerated configuration/bootstrap/safety files.

### P05-R2-B9 — Communication ACL evidence does not prove an authorized real-parent path

The positive gate uses fake/nonexistent parent IDs and proves only rejections. Adapter fallback can use a resource ID as tenant ID when no tenant scope is found. R2 must seed real parent, actor, target, and tenant records; prove an authorized same-tenant path succeeds; then prove inaccessible parent, unauthorized target, and cross-tenant mention fail. Mention + notification + audit + outbox atomicity/deduplication must use the production transaction path.

### P05-R2-B10 — Session replay evidence does not prove family revocation

The positive auth gate observes that replay throws, but does not query every live session in the family afterward. It must prove that the replacement session is also revoked, concurrent rotation has exactly one winner, mismatch replay cannot deadlock, and family revocation persists despite the rejection being surfaced to the caller.

### P05-R2-B11 — Ownership/test coverage can be satisfied by existence-only tests

Generated module specs only assert that a module class is defined. Ownership coverage is calculated solely from the presence of an owner marker, while purpose, dependency, public-interface, data-owner, and meaningful-test completeness are reported independently but do not affect the 100% coverage threshold. Boilerplate OWNER files and existence-only tests are not sufficient evidence of module behavior or change isolation.

The registry gate must validate every required ownership field and classify test depth honestly. Existing domain test depth may be baselined, but P05 cannot call it 100% meaningful coverage merely because seven-line files exist.
