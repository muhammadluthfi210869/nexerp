## Blocking findings

### P06-R5-B1 — Required E2E environment is not self-resolving

The committed test requires `P06_TEST_ADMIN_URL`, but the ordinary repository environment does not provide it. The frozen prompt allowed `P06_TEST_ADMIN_URL` **or the approved repository local database configuration**. The test does not safely derive an admin URL through the existing P06 safety helper, so the documented mandatory command fails all tests before setup.

### P06-R5-B2 — E2E process leaks Nest/Prisma handles

Audit and outbox fault tests intentionally do not close their alternate Nest applications. Jest reports open asynchronous handles and does not terminate after printing 16/16 assertions. A command that requires manual interruption is not exit-code-0 certification. Build isolated module graphs with independently owned Prisma pools and close every app/module/pool in `finally`.

### P06-R5-B3 — Concurrency test accepts zero successful work

The concurrency helper asserts only `master_count <= 1` and `execution_count <= 1`. If both requests reject and both counts are zero, the test passes. It does not require two deterministic successful/replay responses, exactly one master effect, one execution record, one audit effect and one outbox effect. Duplicate `11b` and `11c` test definitions inflate the displayed count without adding distinct coverage.

### P06-R5-B4 — Restart-safety test does not restart anything

Invariant 9 invokes the same `importExportService` instance twice. It no longer constructs a fresh service/Nest application and therefore does not prove persistence across restart/new instance despite its description.

### P06-R5-B5 — Authorized regression-gate amendment was not implemented

The R4 prompt explicitly required the regression gate to execute P01, P02, targeted backend E2E, targeted frontend tests and both typechecks. The committed gate runs only the two typechecks and comments that all other checks happen upstream. Consequently the SHA-bound certifier can pass while the mandatory E2E command fails or hangs. External unbound claims are not sufficient.

### P06-R5-B6 — Test provisions schema with forbidden destructive shortcut

The E2E suite runs `prisma db push --accept-data-loss` and sets an AI dangerous-action consent variable. This conflicts with the migration discipline established in P04 and bypasses the committed migration chain. Even on a disposable database, certification must use `prisma migrate deploy` through the existing safe isolated-database helper; it must not normalize `db push --accept-data-loss` as an ERP verification mechanism.

### P06-R5-B7 — Fault-injection module graph is duplicated and not cleaned

The main application correctly boots `AppModule`, but fault tests import `AppModule`, `MasterModule` and `AuthModule` together, duplicating providers/module graphs. They then leave the alternate apps open. Use `AppModule` once with provider overrides and a separately owned disposable Prisma provider so closure cannot poison the main application.
