## Blocking findings

### P05-R1-B1 — Eight critical gates are hardcoded PASS

`scripts/ssot/lib/p05_certification.js:201-211` constructs callbacks for auth/MFA, permission, tenant isolation, immutable audit, maker-checker, outbox, communication ACL, and error contract that only return `{ pass: true }` and invented mutation counts. No application service, HTTP route, Prisma control, or failure case is executed. The resulting zero-millisecond checks are therefore synthetic despite being labeled `synthetic: false`.

### P05-R1-B2 — The 31-mutation suite self-declares PASS

`scripts/ssot/test_p05_platform_negative.js:38-50` creates `mutationResult()` with unconditional `status: 'PASS'` and `production_path: true`. Most mutations only create an ignored temp file or return a descriptive string. They do not invoke the named production gate, observe a rejection, or validate the expected `gate_id` and `reason_code`. Even the domain-cycle mutation calls a gate scanning the repository while its cycle fixture is outside the repository, ignores the returned PASS, then self-declares the mutation PASS.

This violates the frozen rule that setup failure, unrelated rejection, or self-declaration cannot count as a successful mutation.

### P05-R1-B3 — The application does not compile

The backend compiler reports:

- `auth.controller.ts`: calls removed `validateUser`;
- `auth.controller.ts`: calls `login` with one argument instead of email/password;
- `auth.service.ts`: assigns `null` where the session input accepts `string | undefined`;
- `auth.service.ts`: calls nonexistent `markMfaCompletedForUser`.

An architecture/platform phase cannot pass while the production backend cannot compile.

### P05-R1-B4 — New platform services are not wired into Nest

`AuthModule` provides only `AuthService` and `JwtStrategy`; it does not register/import `SessionService`, `MfaService`, `AuditService`, `PolicyService`, or a platform module. It still uses `process.env.JWT_SECRET || 'ERP_SECRET'` and a one-day JWT lifetime, contradicting the fail-closed configuration and 15-minute access-token contract. The application module does not import `PlatformConfigModule`. Other newly added platform controls are largely isolated files rather than active application boundaries.

### P05-R1-B5 — Authentication and MFA controls are incomplete or unsafe

- `AuthService.login` returns literal access token `opaque`, not a signed 15-minute token bound to a session.
- Refresh mismatch raises `REFRESH_REPLAY` but does not revoke the token family; throwing inside the same transaction would also roll back a revocation unless structured carefully.
- MFA accepts any six-digit value instead of verifying RFC 6238 TOTP.
- MFA encryption derives a key from the committed fallback string `p05-default-key` when configuration is missing.
- The integration helper hashes refresh material with bcrypt cost 10, contradicting the canonical cost 12.

### P05-R1-B6 — RBAC and tenant enforcement contain simulated allow paths

`PolicyService` comments explicitly state tenant resolution is simulated and “any role works.” It does not load actor permissions/data scope from persistent actor-at-event state. Division denial depends on a magic actor ID. Consequently tenant, role/permission, export/batch, and field-scope claims are not proven.

### P05-R1-B7 — Communication, approval, error, and configuration controls are not production-complete

- Communication adapters fabricate `tenant-of-<parentId>` and make the current actor the owner rather than resolving real parent records and tenant/ACL state.
- Maker-checker integration uses raw SQL and asserts `requestedById === maker` as proof that self-approval was blocked; no production rejection is invoked. Multiple-threshold distinct-checker and version enforcement are absent.
- The canonical error file is a factory/registry, not a global HTTP exception filter wired into Nest.
- Configuration ownership is checked mostly by file presence; active modules retain direct environment reads and weak fallbacks.

### P05-R1-B8 — “Integration tests” do not test production services and exit nonzero

The helper runs raw INSERT/UPDATE statements rather than instantiating the production Nest module/services. It leaves a second PostgreSQL client connected, terminates it during database drop, and emits an unhandled `57P01`, producing exit `1`. The certifier never invokes this helper, so its failure does not block the token.

### P05-R1-B9 — Architecture and evidence gates contain fabricated metrics

- `architecture_fitness_suite` only checks that five JavaScript functions exist; it does not run compiler, lint, build, unit, or integration suites.
- complexity and duplication gates force target count to at least one and report duplication percentages as literal zero.
- representative change reports three archetypes as passed without executing three mutations or targeted test selections.
- dependency baseline and candidate digests are identical despite a large candidate diff.
- the scope manifest is generated with empty `changed_paths`, `owners_touched`, and `reasons`.
- ownership reports only 8 modules with tests while still claiming 100% complete ownership coverage.
- required physical manifests and `_p05_test_results.json` are not written; only in-memory hashes are supplied.

### P05-R1-B10 — The frozen wrapper validates shape, not truth

The unchanged wrapper correctly validates IDs and result shape, but the implementation can label invented callbacks and mutation summaries as real. Remediation must make the implementation generate independently inspectable command, persistence, mutation, and manifest evidence; the frozen wrapper/contract must remain unchanged.
