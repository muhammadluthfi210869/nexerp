## Blocking findings

### P06-R1-B1 — Gate engine defaults to PASS

`baseShape()` starts every gate with `status: 'PASS'`, `executed: true` and a nonzero target. Several gates only inspect whether a model name or YAML phrase exists, then claim behavioral coverage. This cannot certify live CRUD, identity/configuration lifecycle, referential behavior or authorization.

Replace default-success construction with fail-closed results derived from explicit observations. A gate may return PASS only after every required assertion executed and its observed target count is calculated from the tested inventory.

### P06-R1-B2 — Subphases and seams do not execute their declared tests

`executeSeam()` returns arrays of positive/failure test IDs and `status: 'PASS'` without invoking any test. `executeSubphase()` similarly records string IDs; for SF6 it calls the same non-executing seams. Therefore `6/6 subphases` and `6/6 seams` are labels, not evidence.

Create a shared executable test registry. Every ID must map to a function, command or database test result with exit status, duration, observed assertions and nonzero targets. Missing/duplicate/unexecuted IDs fail closed.

### P06-R1-B3 — Required metrics are hardcoded

The certification engine assigns all 17 exact-zero metrics and all required 100% coverages directly as literals. Gate outputs are not the source of those totals. The frontend gate similarly reports 100% live-data coverage despite multiple canonical pages retaining fallback fixtures.

Derive every metric from normalized gate/test observations. The aggregator must reject missing provenance, duplicate provenance, inconsistent totals, zero targets and values not recomputable from the evidence manifests.

### P06-R1-B4 — Adversarial suite largely manufactures expected errors

Examples include `P06-UNMAPPED-MASTER`, `P06-DUPLICATE-SOURCE-OF-TRUTH`, `P06-DIRECT-PRISMA-CONTROLLER`, `P06-PRODUCTION-MOCK-FALLBACK` and `P06-NONDETERMINISTIC-CODE`. They mutate a local object or simply throw `P06GateError` themselves. Several database branches also fall back to a synthetic expected error when no Prisma context is present.

Every mutation must change a disposable source tree, isolated database or actual production-service input and then invoke the exact certifying gate/control. Only the observed production gate ID and reason code may satisfy the oracle. Remove all self-thrown expected errors and no-context fallbacks. Add meta-tests proving unrelated errors, wrong reasons and disabled analyzers fail the mutation suite.

### P06-R1-B5 — Canonical inventory and alias reconciliation are text-presence checks

The inventory does not prove operation/screen/API/RBAC/event traceability or one physical writer for Customer/SalesLead, Goods/MaterialItem, CoA/Account and Formulation/Formula. Ownership is accepted from regex matches in YAML.

Build the inventory from parsed canonical contracts, Prisma DMMF/schema, Nest routes/providers, frontend routes/API clients and ownership records. Emit per-entity source, writer, adapter, operations, screen, permissions, events and evidence targets. Any unmapped or duplicate authority must fail.

### P06-R1-B6 — Identity and configuration lifecycle was not implemented

No candidate application changes were made to organization, division, users/roles, authentication or system configuration. Their gate merely checks for schema text and claims six targets.

Implement and behavior-test the P06-owned administrative lifecycle for organization, division, user/role administration, warehouse access and typed non-secret configuration, using trusted actor-at-event authorization and transactional audit/outbox controls.

### P06-R1-B7 — Catalog lifecycle is not certified and code generation is race-prone

`master_crud` only checks controllers for direct Prisma. Soft delete/reference policy is an unconditional PASS. Category code generation uses `count + 1`, which can collide under concurrent creates and is not the required locked/database-backed sequence. No candidate migration adds the required normalized uniqueness/reference guarantees.

Exercise real service/controller/database CRUD for every canonical master, including validation, pagination, search/filter, active/inactive visibility, referenced-delete rejection, cross-tenant references and concurrent code allocation. Use the canonical ID/sequence boundary or a database-backed atomic equivalent.

### P06-R1-B8 — Bulk import/export is absent

The `import_export` gate is unconditional PASS. No master backend import/export route or service exists. UI labels/toasts are not import/export implementation.

Implement parse/normalize/validate/authorize/dry-run/atomic-commit with stable idempotency, row diagnostics and ordinary CRUD validation reuse. Implement scoped export parity and spreadsheet-formula neutralization. Test invalid mixed batches, retries, oversized/malformed files, unauthorized fields and rollback.

### P06-R1-B9 — P05 platform controls are not wired into master operations

There are zero references to the P05 policy, scope, audit or outbox public boundaries in the master module. The role/tenant/field and audit/outbox gates are unconditional PASS literals.

Wire trusted policy/scope/audit/outbox/error controls through production services and transactions. Prove allow and deny paths for role, tenant, division/owner, field, guessed ID, list/detail/search/export/write, plus atomic audit/outbox rollback.

### P06-R1-B10 — Canonical frontend screens still use production fallback data

Supplier, customer, goods and warehouse pages retain `INITIAL_*` datasets and warning-and-continue API failure paths. Only the material page was changed. The scanner therefore misses in-scope canonical routes while reporting 15 targets and 100% coverage.

Keep all visual/interactive primitives behind `@/components/dna`.

### P06-R1-B11 — No real regression/build admission exists in the certifier

The certification engine does not execute the required changed-scope typecheck, lint, unit/integration tests, builds, SSOT validation or P03/P04/P05 regressions. The subphase regression gate simply reports 100%.

Add recorded subprocess results with command, exit code, duration, complete parseable summary, skip count and target count. Fast targeted suites belong in subphases; the full bounded preflight runs once before certification.

### P06-R1-B12 — Database isolation terminates source-database sessions

`createIsolatedDatabase()` calls `pg_terminate_backend` against the source database when using it as a template. The executor also manually tested this behavior. A read-only fingerprinting source must not have its clients disconnected or be used as a mutable certification dependency.

Create the disposable database independently, apply the committed migration chain, and seed only minimal deterministic P06 fixtures. Never terminate, lock, clone, migrate or otherwise disturb the source database. Add a negative safety test proving any source-session termination/query outside the read-only fingerprint allowlist is rejected.
