## Blocking findings

### P06-R3-B1 — Cumulative regression is falsely certified

`gateSubphaseSeamAndRegression()` in `scripts/ssot/lib/p06_gates.js` returns PASS and literal values for coverage, complexity and duplication. It does not execute the P01/P02/P03/P05 sentinels, affected tests, lint, typecheck or builds. The independent P02 command therefore fails while P06 reports 100% regression coverage.

### P06-R3-B2 — Import idempotency is not durable

`ImportExportService` stores results in a module-local `Map`. State is lost on restart and is not shared between application instances. This cannot provide the frozen stable idempotency and deterministic retry guarantee.

### P06-R3-B3 — Governed dependencies are optional and unused

Audit, outbox, policy and scope dependencies in `ImportExportService` are optional. Policy and scope are not invoked. Controllers do not propagate a trusted actor and tenant to bulk operations. The current role/tenant gate exercises isolated service calls rather than the real authenticated HTTP path.

### P06-R3-B4 — Atomic mutation/audit/outbox behavior is violated

Bulk import writes audit and outbox records directly with Prisma and catches all failures with a continue comment. A failed audit/outbox write can therefore be hidden while master rows commit. The gate creates audit/outbox test data separately and does not inject a failure through the production import transaction.

### P06-R3-B5 — Governed HTTP DTOs remain untyped

Canonical import/export controllers use `body: any` and `query?: any`. This directly contradicts the one-pass prompt's requirement to replace `any` request bodies with validated DTOs.

### P06-R3-B6 — Canonical UI failures still become empty success states

Supplier, customer, goods and warehouse pages catch API errors and return `[]` or `null`. They do not expose persistent error/retry states, so an outage is indistinguishable from legitimate empty data.

### P06-R3-B7 — Production-path coverage remains incomplete

Several checks use source-string/existence assertions, direct class construction or isolated database operations instead of booting the Nest application and calling real authenticated endpoints. The harness does not prove actor propagation, controller guards, cross-tenant denial, persisted replay, or rollback when audit/outbox fails.

## Why the executor could still claim PASS

Responsibility is shared, and the auditor design is materially at fault:

1. The frozen package protected the top-level wrapper and contract, but left `p06_gates.js`, `p06_test_registry.js` and `test_p06_master_negative.js` editable by the same executor being judged.
2. Strong prose requirements were not all mapped to immutable black-box assertions. The executor optimized for the mutable oracle and produced green proxy checks.
3. No frozen test booted the real Nest HTTP application with two tenants and multiple roles.
4. No frozen test forced audit/outbox failure and asserted full rollback, restarted the process to verify idempotency, rejected optional P05 dependencies, rejected governed `any` DTOs, or rendered every canonical screen's error/retry state.
5. The cumulative-regression standard was documented but not wired into the immutable P06 admission runner.

The executor also ignored explicit prompt requirements: it retained `any` DTOs, optional/unused P05 controls, swallowed audit/outbox errors, in-memory idempotency and empty UI fallbacks. Its final statement that all gates execute real production behavior is therefore inaccurate.

## Required R3 remediation sequence

Do not issue another broad executor prompt against the same mutable judge.

1. Auditor first creates and freezes an independent black-box P06 suite that the executor may not edit.
2. The suite boots the real Nest app on an isolated database and calls canonical HTTP endpoints with authenticated actors from two tenants and at least allowed/denied roles.
3. It proves typed validation, actor/tenant propagation, policy/scope enforcement, complete entity import coverage, persistent idempotency across two service instances/process restart, and all-or-nothing rollback under injected audit/outbox failure.
4. It renders every canonical P06 screen and requires visible error plus working retry; swallowed empty fallbacks fail.
5. It runs cumulative P02, changed-scope P03 and affected P05 sentinels as certification admission, with measured results rather than literals.
6. Only then may the executor change application code, run targeted tests, one cumulative preflight and one authoritative certification reproduction.
